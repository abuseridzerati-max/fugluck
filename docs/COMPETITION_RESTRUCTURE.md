## Product rules — BUILT locally; hosted rollout PLANNED

- One entry per tournament; 2, 4, 8 or 16 entrants; no byes. Standard materializes on demand from four templates per certified game. Default reference fees retain Space Blaster 500 and Cyber Hopper 400 tetri.
- Creation freezes type, reference fee, actual entry, capacity, rates, prize, margin/subsidy, rules and scheduling configuration. Integer basis-point multiplication rounds the prize **down** to the nearest tetri; Standard margin is the remaining scheduled total. Standard prize is 90%; Promo is 150% with paid reference entry; GIFT is 150% of the reference total with zero entry. Settlement uses the frozen prize, never a collected pot formula.
- Promo boundaries: 00:00 / 06:00 / 12:00 / 18:00 Asia/Tbilisi. GIFT: daily 00:00 Asia/Tbilisi. Registration closes five minutes before start by default; exact cutoff is closed. Full specials wait until their scheduled start; underfilled specials refund. Capacity rotation is configurable (Promo defaults 2/4/8/16; GIFT defaults 16). Server timestamps and durable cycle IDs control eligibility.
- Promo 5 and GIFT 10 independent, per-game progress tracks. Count a participant once only after the entire Standard tournament settles validly, with actual gameplay evidence for that participant. No qualifying credit for sandbox/test/mock/synthetic/admin-fixture/invalidated/refunded/voided play. This deliberately defers early-elimination credit until tournament validation. Qualification from real-money play is not activated by this change.
- At threshold, one ticket targets the nearest future cycle whose cutoff has not passed. Freeze that track until its target cycle ends, including after consumption. No carry-over, banking or cross-game credit. Consume with durable admission; failures must preserve/recover the entitlement. A platform void before any valid play replaces an accepted ticket with one for the next eligible cycle; after valid play, refund without qualifying credit. Old tickets retain audit history.
- Use the existing competition template/instance/participant/accounting model. Persist all bracket slots and a secure server shuffle at lock. Each bracket match uses the existing Level 3 authority run/session/result/decision structure; rematch attempts share a bracket-match lineage. Later slots can be filled only by prior authoritative winners. Only the Final authorizes prize settlement.
- Equal authoritative scores require a rematch; no arbitrary tiebreak. Existing reconnect fencing/grace is retained. One ready/admitted participant against an absent opponent may win by a server-recorded no-show. Both absent means tournament void/refund. Interrupted authority state retries a match using a new fenced attempt; bounded repeated infrastructure failures void/refund. Completed rounds never replay or disappear.

## Exact lifecycle and eligibility policies

- **BUILT, verified in source and recovery tests:** Standard rooms time out after two minutes unfilled by default, returning reservations; the template remains available and the next join creates another room. Tests that admit sixteen remote-database fixtures use a longer isolated test configuration. Special events close five minutes before start and never start partially filled. A full special captures entries once and waits until its scheduled start.
- **BUILT, verified in source and qualification tests:** only immutable `LIVE` Standard provenance is eligible for qualification. A settled tournament must have an applied authoritative Final winner; each credited participant must have a positive-tick receipt from an applied win/forfeit decision. The event key is `(tournament, user)`, irrespective of rounds played. Settlement of the entire tournament is required, including for eliminated players. All platform-voided tournaments are excluded, even after legitimate gameplay; this conservative policy avoids rewarding refunded/uncertain outcomes. Invalidation is irreversible and closes ticket admission and player eligibility display.
- **BUILT, verified by genuine sandbox/mock tests:** this release creates `SANDBOX` public products and guarded `STAGING_MOCK` operator products. Neither earns qualification. `LIVE` admission is denied, so Promo/GIFT are intentionally locked for ordinary test accounts; positive qualification tests use explicit fixtures in disposable schemas. There is no public ticket grant or qualification bypass.
- **BUILT, verified in recovery tests:** leaving an unfilled room cancels the whole room and returns every entry, preserving the existing cancellation model. The voluntary caller's special ticket stays consumed until normal expiry; other admitted players receive a linked next-cycle replacement. Platform cancellation before any positive-tick receipt replaces all accepted tickets, including delayed recovery after expiry. Repeated recovery cannot duplicate replacements. An already available later ticket coalesces the replacement; an already consumed later ticket defers replacement until that entitlement expires. Progress remains frozen against the replacement cycle. No replacement follows valid recorded play.
- **BUILT, verified in configuration/immutability tests:** configuration revisions are operator-domain operations with an actor ID; there is no new public configuration endpoint. Rates (10%/150%/150%) and periods (6h/24h) are protected by validation. Fees, allowed capacities, special rotations, thresholds, cutoff, readiness, waiting and retry limits are bounded. Existing product, cycle and instance snapshots stay unchanged. Old Standard rooms can finish on their frozen revision; a retired revision cannot create another room. Current catalog discovery uses the new revision.
- **BUILT, verified by code and schedule tests:** Asia/Tbilisi and UTC are the supported named zones. Other zones are rejected rather than approximated. Each target cycle expires at the following boundary, even when its tournament finishes earlier. A qualified track resumes from zero after that boundary; expiry is projected on reads and persisted on the next transactional admission/completion/replacement. No unlimited catch-up event generation occurs after downtime.

## Persistence and recovery

**BUILT, verified in migrations, model tests and genuine authority play:** nine new tables hold config revisions, cycles, products, tournament roots, bracket matches, entry intents, qualification events, tracks and tickets. Authority runs gain optional bracket/attempt references. The legacy one-run-per-instance constraint becomes a partial legacy constraint plus unique bracket-attempt and live-bracket constraints. SQL triggers protect frozen terms, seeds, bracket slots/winners, prize schedules, ticket ownership/target/source/consumption, completion evidence and irreversible invalidation.

Admissions serialize per product, use a durable intent before reservation, and accept a seat and ticket in one transaction. Unknown reservation replies retry the original financial key; rejected admissions release reservations. Full tournament capture and bracket creation recover independently. Every match has two fresh authority sessions. Applied decisions fill fixed parent slots exactly once. Only the frozen Final authorizes commercial/sandbox settlement; a failed final payout leaves durable `FINALIZING` state for retry. Existing append-only commercial postings, zero-sum checks, margin, subsidy and prize-obligation accounts remain the financial source of truth.

The server draws a 256-bit random seed after full admission. HMAC-SHA256 counter output and rejection-sampled Fisher–Yates shuffle a canonical entrant list. The seed, order and SHA-256 commitment are persisted once and withheld from player projections. This is an auditable server draw, not an externally verifiable pre-registration randomness ceremony. Each game match uses a separate authority seed. The deployment continues to require one active game-owning server process; distributed socket routing is outside this change.

## Existing UI integration

Added fields cover product, capacity, frozen terms, both progress tracks, target/next cycles, locked state, tournament/round/current match and optional named bracket. ## Implementation sequence

1. Immutable economics/configuration, additive persistence and cycle calculation.
2. Durable qualification audit/tracks/tickets and atomic admission recovery.
3. Persisted bracket generation, authority attempts, advancement and Final-only accounting.
4. Extend the existing player read model and simplified UI with type, progress, cycle, round and current/next match.
5. Economics, concurrency, schedule, qualification, bracket/accounting and genuine local authority tests; complete regression/build/schema checks.
6. Coherent local commits and exact staging backup/restore/migration/deployment plan. No hosted migration or deployment without the required approval.

## Deployment boundary
