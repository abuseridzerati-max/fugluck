  routes to list in-memory active matches (id, players, currency, stake).

  hand-written policy comment documenting the win/loss/void decision matrix

  comment. The underlying logic for that part is unchanged, but the
  documented rationale is gone. New logic was *added* (not replacing
  anything) for trivia-style outcomes: primary ranking by `correctCount`,
  tiebreak by `totalResponseTicks`, falling through to the original
  score-comparison logic for other games.
- `packages/server/src/db/schema.ts` (modified) — adds `role`, `status`,
  `statusReason`, `createdAt` to `users`; adds a whole new
  `adminAuditLogs` table; adds `status`/`statusReason` to `matchesHistory`;
  adds a new `triviaQuestions` table. **No migration file exists for any of
  this** — see section 4, this is real schema drift.
- **`packages/server/src/routes/admin.ts` (new, untracked, 634 lines)** —
  an entire admin console API surface: user search/suspend/ban/unban, match
  view/void-with-refund, ledger view, **grant COINS**, **grant DIAMONDS**,
  **reverse a ledger entry**, and an audit-log explorer. Every mutating
  route requires an explicit `reason`, an idempotency key (deduped against
  `adminAuditLogs.idempotencyKey`), and writes an audit log row. Self-grant
  to the acting admin's own account is explicitly blocked
  (`targetUserId === adminUserId` → 403). Amounts are capped at 100,000 and
  validated as finite positive integers. Voiding a match with `stake > 0`
  issues compensating ledger refunds to both players.
- **`packages/server/src/auth/permissions.ts` (new, untracked)** — defines
  4 admin roles (`SUPER_ADMIN`, `ADMIN`, `MODERATOR`, `SUPPORT`) and a
  permission matrix; `requirePermission(permission)` middleware checks the
  DB-stored role (not anything client-supplied).
- `packages/server/src/auth/middleware.ts` (modified) — `requireAuth` now
  does an extra DB lookup per request to reject `banned`/`suspended`
  accounts; adds a new `requireAdmin` that checks role is one of the 4 admin
  roles. Note: `requireAdmin` is defined but **admin.ts uses
  `requirePermission(...)` instead of `requireAdmin`** everywhere — so
  `requireAdmin` currently appears to be dead code (unused export). Worth
  confirming intent.
- Client-side: `/admin` is now a reachable client route
  (`packages/client/src/App.tsx`) that renders the new
  `packages/client/src/admin/AdminConsolePage.tsx` (untracked, ~25KB) for
  **any authenticated user** — there is no client-side role check gating
  the route. This is not itself a vulnerability (every admin API call is
  independently permission-checked server-side, confirmed above and in the
  passing `admin-security-check`/`admin-console-check` test scripts), but a
  non-admin visiting `/admin` will see the console UI shell before its API
  calls fail with 403s. Cosmetic, not financial.
